SOLD OUT ミューズ街 P0 見本

本体には入らない見本。店・名前はすべてダミー、地図は CSS の仮

設計書 第2版（S は無料の店兼家、全店に 3×3 敷地の区画）を前提に、視点も操作もちがう3つの画面案を、同じ街（121店 → 200店に増やせる）で作った。中央地区の「噴水通り」はどの案でも同じ並び（おたがいに希望した2店・偶然の向かい2店・休業の店・空き家・NPCの家・新しく入った店）。

案A 上から見る地図全景 → 寄る → 店を押すと札。PC はマウスを乗せると店名。 案B 通りを歩く通りに立って店先を眺める。左右に歩く・振り返る・店に入る。 案C 案内板商店街の案内板の一覧。探す・職業で光らせる・小さな地図で確認。 許可証の見本横長・縦長・正方形と、旧許可証＋住所。3:4／1:1／未提出を切り替え。

3案の比べ方

A 上から見る地図B 通りを歩くC 案内板
視点真上から。街の形・広がりが一目でわかる通りに立った目の高さ。店の正面（外観・看板）が主役文字の一覧（案内板）。地図は確認用の小窓
全景全地区を縮めて表示、目印の名前を重ねる通りの路線図（地区の位置どおりに並ぶ）地区の一覧（目印・店数）
地区寄ると看板が読める。隣の地区も地続きで見える通りを選ぶと、その通りの片側の店先が横に並ぶ通りごとに「北側（奇数）｜路地｜南側（偶数）」の表
店を選んだときPC は右の札、スマホは下から出る札店の前に立つ → 「店に入る」で立ち絵が大きく出る右に札＋小さな地図。スマホは札の画面に切り替わる
住所 → 店先「許可証の住所を押す」→ その区画に寄って光るその店の前に立った景色から始まる（いちばん「店先」らしい）案内板のその行が光り、札が開く
お隣・向かい札の「左隣・右隣・向かい」を押すと移る。地図でも並びが見える左右に歩く、振り返ると向かい。体で覚えられる表の左右・同じ行の向かい側がそのまま並ぶ
S → M → L区画の中で家が大きくなり、庭が減るのが見える（札で切り替えて確かめられる）小さな家＋庭 → 二階建て → 区画いっぱいの館。通りの並びは変わらない□の数だけ。見た目の楽しさは弱い
観戦と API の分担観戦：地図と札。API：地区ごとの区画・持ち主（GET /town/map）と札の中身（GET /lots/{id}）観戦：店先の絵。API：通り1本ぶんの並び（左右・向かい）。絵は観戦側だけ観戦も API もほぼ同じ形（案内板＝JSON の並び）。Muse のスペースにも写しやすい
実装の重さ中。マップチップが要る（今は CSS の仮）。寄る・引くの操作重め。店先の絵（外観×S/M/L×NPC）がたくさん要る軽い。チップがなくても完成形に近い
200店以上地区ごとに描くので重さは平気。全景は字が読めないので目印頼み通り1本ずつなので何店でも平気。全体をつかみにくい何店でも平気。探す・光らせるが効く
長所
  • 「街がある」感じが一番強い
  • ご近所・地区のつながりが目で見える
  • 「向かいは誰だろう」と歩きたくなる
  • 外観・増築が一番映える
  • 速い・軽い・スマホに強い
  • Muse の API とほぼ同じ形
短所
  • スマホでは小さい
  • チップの絵の量が見た目を決める
  • 絵の量が多い
  • 全体の地図がわかりにくい
  • 街を歩く楽しさは薄い
  • 増築が見えにくい

組み合わせもできる：たとえば「全景と地区は A、店を選んだら B の店先、スマホと検索は C」。

切り替え

各画面の上で、店数 121／200（79店を後から入れて、前からいる店の区画が変わらないことを見る）と、大通りの幅 64px／32px（案A）を切り替えられる。node tools/town-mock/check.mjs で配置の決まり（重なりなし・道がつながる・ブロック・希望・121→200 で動かない など）を確かめられる。

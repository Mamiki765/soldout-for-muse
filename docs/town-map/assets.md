- 既定では大通り96px、路地64px、川は東西に直進する64px幅。橋は南北方向で128px長。陸への延長は両岸で各32px。幅は大通り96px、中央の南北通り64px。P0の道幅切り替えでは大通り64pxと路地32pxがあり、32pxの中央通りを正式に採る場合は両側の欄干を1列に収める橋を追加する。川が曲がって東西方向の橋が必要になれば、光向きと岸に合わせて描き分ける。
- 中央は西 `d01`・東 `d02`。各チャンクは自地区と西・北の大通り（北西交差点を含む）を所有する。中央軸は段差のない石畳で、並木と街灯が両端に並び、川の上は大通り幅の橋。地形の継ぎ目はチャンク境界に現れないようにする。
- `tiles.html` の市場大屋根は4×4とあるが、既定の `market`・`stalls` は各10×4の矩形が2組ずつ。地区8列の比較モードでは各16×4。屋台の2×2は部品寸法として活用する。池と東屋は生成済みで、正式素材では岸の左右・角と東屋を追加する。東屋は幅3チップを中央に置くため、既定のX座標に半チップが入る。スプライトは整数ピクセルで配置する。 [中央施設の生成](https://github.com/Mamiki765/soldout-for-muse/blob/2f3236d562ac028e16e2ace17be5135609930f12/tools/town-mock/town-gen.js#L902-L993)

## 地形、橋、小物

サイズは処理後の原寸。地形は不透明、重ねる素材は領域外を完全透過。ここに挙げる地面・水・公共物の色は街の共通色。出店者が変更する部位は店舗の項に示す。

| 素材 | 原寸と透過 | 用途と接続条件 |
| --- | --- | --- |
| 野草地 `grass`、芝 `lawn` | 各32角・不透明 | 野原と手入れされた庭・公園の基底。基本と控えめな差分を作る。差分間で端の色・形を合わせる。 |
| 大通り `avenue`、歩道 `curb`、広場 `plaza` | 各32角・不透明。縁を重ねる場合は透過 | 同系石材。大通りの接続と交差点、歩道の縦横・切れ目・端、中央軸のフラットな舗装。広場は繰り返しても市松模様が出ない目地を使う。 |
| 土路地 `alley`、小道 `path` | 各32角・不透明。小道を重ねる場合は透過 | 路地は面・草側の辺・角・出入口。小道は縦横・端・L字を基本に、園路の合流で必要なT字・十字を足す。店先の敷石は扉の地面側アンカーにつなぐ。 |
| 花壇 `flowerbed`、畑 `field` | 各32角・土は不透明。枠・葉・花は透過可 | 花壇の縁は始端・中間・終端と角。畑は畝の向きと条間を連続させ、畝端を閉じる。 |
| 並木帯 `hedge` | 地面32角は不透明。生け垣や樹木は透過 | 帯の縦横・端と必要な角を持つ。大通りや橋を横切る位置では端で止める。 |
| 川と池 `canal` | 水面・岸は32角。不透明な基底、必要に応じて透過の岸縁 | 直線の川は水面・北岸・南岸。池には東岸・西岸と外角・内角各4方向の形を用意し、使う形を配置に合わせて選ぶ。池は水の色を共有し、反射・植生・岸の幅で区別できる。未接続の端や曲がりが加われば終端を追加。 |
| 橋 `bridge` | 南北の組立寸法96×128pxまたは64×128px。床・橋台は不透明な部分を持ち、欄干や影は透過 | 北橋台、水上2行、南橋台。3列幅は左欄干・床・右欄干、2列幅は左右欄干と内側の通行面。P0一覧の9＋6の役割を床・欄干・橋台の共用で満たせる。欄干の始端、中継、終端と舗装への取合いを検品。橋の下で岸を二重に描かない。 |

地面同士が切り替わるところは、使用する地形の組み合わせごとに、必要な辺、内角、外角を用意する。差分の輪郭は各セルの端で同じ形と色を持たせる。水・地面・道・枠で同じ役割の素材は重ね合わせを使い、全方向の組み合わせを別画像として抱えない。

| 透過小物（`deco`） | 原寸 | 設置・接続 |
| --- | --- | --- |
| 木、街路樹、植え込み | 各32角から開始 | 木の根元を地上に固定。樹冠・影を別部品にできる。並木で輪郭差分を混ぜ、通行面と橋台を塞がない。 |
| 街灯（P0のガス灯）、ベンチ、鉢、郵便受け、木箱 | 各32角 | ポール・脚・底を接地点にする。街灯は道路の縁、郵便受けや鉢は入口を避けて設置。文字を描き込まない。 |
| かかし、葦、花 | 各32角 | かかしは畝の間、葦は護岸・池の縁、花は草地や花壇。隣のセルの道や水に出る場合は描画範囲を宣言する。 |

## 店舗兼住宅と状態差分

| 素材 | 原寸と透過 | 設置・色変更 |
| --- | --- | --- |
| 店舗 S / M / L | 64 / 128 / 192px角 × 北向き・南向きの計6形。背景透過 | 北・南それぞれの戸口の足元を基準に園路・敷石を接続。屋根、壁、扉、縁に部位マスク。店主が上書きできるのは屋根と扉。光向きと金具・目地・窓は共通。 |
| NPC住宅 S / M | 64 / 128px角 × 北向き・南向き。背景透過 | 店舗の共通部品を使い、日よけや商店用看板を外す。プリセットはNPC用。敷地にはSを2軒、Mを1軒、Sと畑などを組み合わせられる。 |
| 日よけ、看板、敷居 | 基本形と同じアンカー。取り外し可能な透過部品 | 日よけは店先を識別できる程度。色を連動させる場合は、屋根色との連動部を明示する。看板の木枠や窓・金具は固定色。 |
| 改装中、閉店猶予 | 各サイズ・向きに合う透過の足場／戸板。閉店猶予は専用の落ち着いた色 | 改装中は足場、閉店猶予は戸板などで識別する。色だけに依存しない。足場や影は隣の通行面にせり出さない。 |

本体の透過PNGに、屋根、壁、扉、縁の同寸・同アンカーのマスクを対にする。マスクは対象外を透明とし、対象内に日向・基準・陰の段を持つ。窓、金具、梁の固定部分や接地影への着色は避ける。同じ絵に対して屋根だけ、扉だけをそれぞれ変更し、該当マスク外のピクセルが変わらないことを確認する。日照の向きはグローバルで固定し、北向きは南向きの単純反転で作らない。

| 素材 | 原寸と透過 | 配置・接続 |
| --- | --- | --- |

| 中央市場の大屋根 | 既定の組立寸法320×128px・透過 | 棟端、柱間、中間床、屋台の位置を分ける。96pxの中央軸や西区内の南北通りを塞がず、地区幅比較では同じ部品で長さを変えられるようにする。 |
| 市場の屋台 | 1台64×64px・透過。既定の列は320×128pxの箱に配置 | 布、木の台、箱を共用。地面は広場の石畳。布の色は市の装飾で、店主カスタマイズとは独立。 |

| 船着き場 | 中央128×96px、小型の目印は64×64pxまたは水辺配置で128×96px・透過 | 北・南の岸に合う陸上取付部と水上の桟橋を別部品にする。P0の中央船着き場の矩形は陸側で終わるため、正式絵では水上への張り出しを描画範囲に含め、橋や護岸との重なりを検品。 |

## 制作順と初回試作

1. **小さな接続見本。** 地面12枚、南北橋1組、S店舗の北向き・南向き。まず草・石畳・土道・川岸を使って同じ地図上の明度と質感を確認する。橋は大通り幅だけ作り、道と川の取合いを確認する。S店舗では入口と敷石、屋根と扉の独立着色を確認する。具体的な提出物は [初回試作プロンプト](first-batch-prompt.md)。
2. **地形の接続と残りの橋。** 歩道・広場・畑・花壇・並木帯、道路の合流、岸の辺・角、必要な橋幅と端部を追加。チャンクをまたいだ川、並木と中央軸で検品する。
3. **商店街。** M/L、NPC住宅、足場と戸板、小物と街路樹。棚の段階によるS/M/Lの違いと、異なる屋根色が隣り合ったときの見え方を確認する。
4. **中央西と東の公園。** 市役所、中央市場、ギルド会館、噴水、大樹、掲示板、船着き場、池・東屋・予定地。初回で決めた地面と屋根の画風を使い、各機能の実装を待たずに配置・美術を進められる。地区の目印は中央・街路の素材を共用しながら拡張する。

### 試作の検品

- **ファイル。** 元の生成画像を別に保存し、セルごとの切り出し、必要な整数倍縮小、原寸でのピクセル修正、透過処理を行う。原寸PNGのサイズ・sRGB・外周の透明・基底の不透明を確かめる。最近傍で拡大し、線をぼかさない。隣のセル色の漏れや、透過の白縁・半透明のごみを明暗二種の背景で確認する。半透明の接地影は本体から分離できる。
- **接続。** 平坦な地面を5×5以上並べ、端の段差と反復を探す。接続辺の基準断面を32pxの位置で照合し、差分の内部模様が継ぎ目に伸びないようにする。草→舗装→3列幅の橋台→橋床→向かい岸、芝→敷石→戸口→土路地を組み、ずれ・水面の穴・岸の二重表示・入口を塞ぐ欄干を検出する。
- **店主色。** 同じSの双方の向きに、少なくとも赤瓦・藍・山吹の屋根、樫・深緑・生成りの扉を当てる。暗色・近似色の組み合わせでも入口・軒が読めること、窓や金具、影が巻き込まれないことを確認する。1倍、2倍・4倍の最近傍拡大、縮小相当（地形1マス16px・8px）の画像を比較する。
- **採否。** Codexが寸法・マスク・接続を確認し、オーナーが原寸と試作地図で造形・質感・視認性を判断する。継ぎ目の不合格は原寸補正か再生成、画風の不合格は共通指示に戻して再試作。整合が取れた組を後続の参照にする。本番向けの最終確認では121／200店と中央東西を含む場面で、引いた表示と狭い画面でも道筋と目印が読めるか確認する。

## 素材の管理と後の組み込み

- 生成原本、補正候補、オーナー採用版を区別する。素材ID、制作指示、原寸、透過、接続辺、部位マスク、採否を記録する。共通キットに入れるのは採用済みの原寸素材とマニフェスト。
- P0の `ground` と `deco` の論理番号は、素材画像の並びや差分番号から独立させる。隣接1マス分（角を選ぶ場合は対角を含む）か、解決済みの接続キーをクライアントに渡せる形にする。差分はワールド座標で選び、チャンクの読み込み順に依存させない。P0の描画は未受信の隣を草地として扱うため、正式版では川の途中に護岸が生えないようにする。 [P0の描画と隣接参照](https://github.com/Mamiki765/soldout-for-muse/blob/2f3236d562ac028e16e2ace17be5135609930f12/tools/town-mock/tiles.js#L294-L331)
- 大施設には施設ID、基準位置、入口、占有範囲、描画範囲・選択範囲を別々に持たせる。複数区画を一棟として扱い、境界を越える描画は所有チャンクの単一IDを参照して一度だけ行う。地面→橋床・接地影→構造物・小物→前景の欄干・樹冠→UIの順を基準にし、同じ層では足元の位置を使う。
- P0の `kit/town/tiles-v1.png` は共通tilesetの参照名。将来のパッケージは、地形・小物のアトラス、大きい建物・施設や部位マスク、共通のマニフェストで構成する案。マニフェストには素材ID、画像矩形、原点、入口・脚などのアンカー、レイヤー、接続種別、パレット版を記録する。チャンクの形式版と素材版は独立させ、配布済みのURLは不変にする。 [P0のチャンク形式](https://github.com/Mamiki765/soldout-for-muse/blob/2f3236d562ac028e16e2ace17be5135609930f12/tools/town-mock/town-gen.js#L1077-L1096)
